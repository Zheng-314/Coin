# 项目分工方案 — 鉴泉识珍

> 冲击国家级大创 | 2026-07-16 | 项目负责人：阿轩

---

## 一、项目目标

### 一句话

构建一个**知识增强的多任务古钱币智能鉴定系统**，实现版式识别→真伪鉴别→品相评级→价值评估的全链路闭环。

### 国家级创新点

| 创新点 | 说明 | 对应产出 |
|------|------|------|
| **多任务联合学习** | 一个 backbone 同时输出版式+品相+分数，共享特征提升小类别精度 | 论文 |
| **知识图谱增强分类** | 用币种间铸造关系、历史背景等图谱信息辅助分类决策 | 论文 |
| **细粒度钱币特征对齐** | 针对同一币种不同版别的微小差异（如"精发"vs"粗发"）设计注意力机制 | 专利/软著 |
| **开放数据集** | 首个公开的中国机制银币多任务标注数据集 | 数据论文 |

### 预期产出

| 产出 | 数量 | 说明 |
|------|------|------|
| 学术论文 | 2 篇 | 一篇方法、一篇数据集 |
| 软件著作权 | 1 项 | 鉴泉识珍智能鉴定平台 |
| 开源数据集 | 1 个 | 10,000+ 枚标注好的中国机制银币 |
| 开源代码 | 1 个 | GitHub 200+ star 目标 |

## 三、分工

### 系统组（3人）—— 让产品能用、好看、能演示

| 角色 | 具体职责 |
|------|------|
| **后端负责人** | Flask API 全部接口完善、GraphRAG+Neo4j 部署、模型推理接口、Docker Compose |
| **前端负责人** | 全页面开发（鉴定结果页、品相页、估值页、知识图谱页）、Element Plus 组件封装 |
| **全栈/QA** | 前后端联调、API 测试（50%+覆盖率）、CI/CD 维护、用户手册、演示视频 |

**第一周必须交付**：Docker 一键启动全系统 + GraphRAG 跑通。

---

### 数据组（2人）—— 把数据集做成核心竞争力

| 角色 | 具体职责 |
|------|------|
| **爬虫+基础设施** | PCGS 爬虫开发运维、图片下载和命名规范化、数据版本管理 |
| **标注+质量** | 币名→92类人工校验、品相/分数字段补全、真伪样本收集、数据质量报告 |

**第一周必须交付**：爬虫跑起来开始产数据 + 修正现有 6,077 对的标签错误。

---

### 模型组（3人）—— 把模型做成学术贡献

| 角色 | 具体职责 |
|------|------|
| **版式识别** | VGG19/ResNet 双路分类、Top-K 评测、混淆矩阵、模型对比 |
| **多任务+知识增强** | 多任务学习框架（版式+品相+分数）、知识图谱特征注入、消融实验 |
| **真伪鉴别+工程** | 真伪鉴别 baseline、ONNX 导出、benchmark.py 评测脚本、模型卡片文档 |

**第一周必须交付**：用现有数据训出版式识别 baseline + 精度报告。

## 四、各组对接接口

```
系统组 ←→ 模型组:  REST API (/predict, /valuation)
系统组 ←→ 数据组:  /api/artifacts/*, /api/kg/graph
模型组 ←→ 数据组:  data/processed/splits/*.csv, metadata.csv
```

| 接口 | 提供方 | 消费方 | 格式 |
|------|------|------|------|
| 训练数据 | 数据组 | 模型组 | CSV（正面图,反面图,标签） |
| 模型权重 | 模型组 | 系统组 | .pt / .onnx 文件 |
| 推理 API 文档 | 系统组 | 模型组 | Markdown（请求/响应格式） |
| 标签映射 | 数据组 | 系统组+模型组 | JSON（classification.json） |

## 七、风险备案

| 风险 | 预案 |
|------|------|
| PCGS 反爬 | 从多个来源爬（NGC、华夏古泉、钱币天堂） |
| 92 类数据不均衡 | 数据增强 + Focal Loss + 长尾学习 |
| 真伪样本难获取 | 先用数据增强造伪样本，再联系鉴定机构合作 |
| 模型训不动 | 用 AutoDL/恒源云等 GPU 云平台 |
| 组员进度跟不上 | 每周站会 15 分钟，GitHub Projects 看板跟踪 |
