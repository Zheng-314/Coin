# 双版本架构方案 — Windows + 华为昇腾

---

## 一、两个版本的区别

| | Windows 版 | 昇腾版 |
|------|------|------|
| **运行在哪** | 笔记本 / 台式机 | Atlas 200I DK 开发板 |
| **操作系统** | Windows 10/11 | Ubuntu (CANN 环境) |
| **推理硬件** | CPU (ONNX Runtime) | NPU (Ascend 310) |
| **模型格式** | `.onnx` (176 MB) | `.om` (从 ONNX 转换) |
| **推理调用** | Python 直接调 `onnxruntime` | 子进程调 `inference_worker.py` |
| **前端** | 一样 | 一样 |
| **后端框架** | 一样 Flask | 一样 Flask |
| **用途** | 开发调试、日常演示 | 正式演示、性能展示 |

## 二、架构对比

### Windows 版

```
Flask (:5001)
    │
    ▼

    │
    ▼

```

### 昇腾版

```
Flask (:5001)
    │
    ▼
subprocess.run(["python", "inference_worker.py", img1, img2])
    │                              ▲
    │   inference_worker.py:      │
    │   1. acl.init()              │
    │   2. 加载 best_model.om     │
    │   3. 预处理图片              │
    │   4. 推理 → Top-3           │
    │   5. print(JSON结果) ───────┘
    │
    ↓
stdout 抓到 JSON → 返回前端
```

## 三、同一套代码怎么兼容两个平台

在 `config.py` 加一个开关：

```python
# backend/config.py

# 推理后端: "onnx" (Windows/CPU) 或 "ascend" (昇腾 NPU)
INFERENCE_BACKEND = os.getenv("INFERENCE_BACKEND", "onnx")

if INFERENCE_BACKEND == "ascend":
    ASCEND_OM_MODEL_PATH = os.getenv("ASCEND_OM_PATH", "./best_model.om")
    ASCEND_DEVICE_ID = int(os.getenv("ASCEND_DEVICE_ID", "0"))
```

在 `services/inference_service.py` 里根据开关选推理路径：

```python
if config.INFERENCE_BACKEND == "ascend":
    result = run_ascend_inference(img1_path, img2_path)
else:
    result = run_onnx_inference(img1, img2)
```

**不需要改前端、不需要改路由、不需要改业务逻辑。** 只替换推理那一步。

## 四、模型格式转换

### ONNX → OM（昇腾）

```bash
# 在 Ascend 开发板上运行
atc --model=best_model.onnx \
    --framework=5 \              # 5 = ONNX
    --output=best_model \        # 输出 best_model.om
    --soc_version=Ascend310P3 \  # 芯片型号
    --input_shape="input1:1,3,224,224;input2:1,3,224,224"
```

### 训练时模型保存两版

```python
# 训练结束后
torch.save(model.state_dict(), "best_model.pth")        # PyTorch 原生
torch.onnx.export(model, ..., "best_model.onnx")        # ONNX (Windows用)

# 然后手动在 Ascend 板上跑 atc 命令转 .om
```

## 五、开发板连接方式

```
笔记本 (Windows)                     Ascend 板 (Ubuntu)
─────────────                       ──────────────
前端 localhost:5173
        │
后端 localhost:5001  ───HTTP───→   后端 :5001
(开发调试用)                         (正式演示用)
        │                                  │
   ONNX Runtime                        Ascend NPU
   (CPU推理)                           (NPU推理)
```

两种连接方式：

```
方式1: 前端笔记本 + 后端 Ascend 板
  笔记本浏览器 → http://Ascend板IP:5001
  前端 build 成静态文件放 Ascend 板上也行

方式2: 全部在 Ascend 板上
  后端 :5001 + 前端 nginx 部署
  笔记本浏览器 → http://Ascend板IP
```

## 六、现有 Ascend 代码分析

`backend/inference_worker.py` 已经是完整的 Ascend 推理程序：

| 部分 | 做什么 | 状态 |
|------|------|------|
| `AscendModel.__init__` | 初始化 ACL 环境、加载 .om 模型 | ✅ 完成 |
| `AscendModel.execute` | 双图推理，返回 NPU 输出 | ✅ 完成 |
| `preprocess_image` | 224×224 归一化预处理 | ✅ 完成 |
| `main` | 接收命令行参数，输出 JSON | ✅ 完成 |

**缺失的部分**：Flask 后端没有调用这个脚本的逻辑。需要加一个 `run_ascend_inference()` 函数：

```python
# 新增: services/ascend_service.py
import subprocess, json

def run_ascend_inference(img1_path, img2_path):
    result = subprocess.run(
        ["python", "inference_worker.py", img1_path, img2_path],
        capture_output=True, text=True, timeout=30
    )
    return json.loads(result.stdout)
```
