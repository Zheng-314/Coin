# 真伪鉴定与多模态问答 · 系统方案

本文档面向两部分人：
- **系统侧**（已完成）：接口、数据契约、前端页面
- **模型侧**（待完成）：如何训练真伪识别模型并接入

---

## 一、三条链路

```
① 版式识别（已有，待换模型）
   两图上传 → YOLO 检测 → 裁剪 → VGG19 双路 → 版别 + 置信度

② 真伪初筛（本轮新建，等模型接入）
   两图上传 → [模型·可选] → 风险等级
            → [必选] 部位级提示（边齿/珠圈/字口/包浆/重量/声音）

③ 多模态问答（本轮接通）
   文字 or 文字+图片 → 版式识别 → 知识检索 → 并入部位提示 → 生成回答
```

三条链路共用同一套图片校验、同一套预处理、同一个限流器。

## 二、真伪初筛：系统侧已完成的部分

### 2.1 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/authenticity/check` | 上传正反面，返回风险等级 + 部位提示 |
| GET | `/api/authenticity/capabilities` | 模型接入状态、部位清单、提示条数 |
| GET | `/api/authenticity/parts` | 提示库，支持 `?part=边齿` 过滤 |

请求（multipart/form-data）：

```
image1  正面图（必填）
image2  反面图（必填）
variety 版式（可选，填了会优先返回该币种相关条目）
```

响应：

```json
{
  "status": "ok | model_not_installed | rejected",
  "risk_level": "高 | 中 | 低 | unknown",
  "score": 0.87,
  "variety": "机制银币 > 地方省造 > 北洋造 > ...",
  "checks": [
    {"part": "边齿", "hints": [{"text": "...", "judged": true, "source": "text_units#12"}],
     "result": "待人工核查"}
  ],
  "model": {"installed": false, "ready": false, "expected_output_dim": 2},
  "disclaimer": "本功能为初筛提示，不构成真伪结论……"
}
```

**关键设计**：模型没接入时接口仍然返回 200 和部位提示，前端正常可用。
这就是"系统搭好、只等模型"的含义。

### 2.2 前端

页面：`/authenticity`（`frontend/src/views/AuthenticityView.vue`），导航栏「真伪初筛」。

页面逻辑：
- 顶部固定风险提示（不构成真伪结论）
- 状态条显示模型是否接入
- 上传两图 + 可选填写版式
- 结果按部位分组展示，含判断词的条目打「含判断」标签
- 没有资料的部位显示「知识库暂无该部位的鉴别资料」，不编造

### 2.3 提示库

`data/authenticity/part_hints.json`，由 `scripts/build_authenticity_hints.py` 从知识语料抽取。

当前规模（真实数据，未做任何补充）：

| 部位 | 条数 |
|---|---|
| 边齿 | 9 |
| 珠圈 | 2 |
| 字口 | 1 |
| 包浆 | 1 |
| 重量 | 0 |
| 声音 | 0 |

**共 13 条，其中 5 条含判断词。** 这个量很小，是因为现有语料里带部位的句子本来就少。
扩量方式见第六节。

## 三、真伪初筛：模型侧要做什么

### 3.1 模型规格（必须严格遵守）

| 项目 | 规格 |
|---|---|
| 文件位置 | `backend/authenticity.onnx` |
| 输入 | `input1`、`input2`，shape `[batch, 3, 224, 224]`，float32 |
| 通道顺序 | **RGB** |
| 归一化 | `/255` 后按 ImageNet 均值方差标准化：mean=[0.485,0.456,0.406]，std=[0.229,0.224,0.225] |
| 输出 | `[batch, 2]` logits，**index 1 = 存疑概率** |
| 输出维度 | **必须是 2**，否则系统按未接入处理 |

预处理代码已写好（`backend/services/authenticity_service.py` 的 `_preprocess`），训练时必须与之一致。

### 3.2 训练数据怎么来（关键，当前没有）

现状：**项目里没有任何假币图像**，`data/raw` 全是真品。这是训练的第一道门槛。

三条可行路径，按推荐顺序：

**路径 A：以真品构造"异常"负样本（最快，成本最低）**

不追求"识别所有假币"，而是让模型学会识别**明显偏离真品特征**的情况：

1. 正样本：`data/raw` 中已评级的真品（7,556 对）
2. 负样本：对正样本做**工艺级退化**，模拟仿品常见缺陷
   - 图案模糊（高斯模糊 σ=1.5~3）→ 模拟翻砂/压铸细节丢失
   - 边缘过锐（锐化 + 阈值化）→ 模拟激光雕刻
   - 光泽丢失（降低对比度 + 加噪）→ 模拟现代电镀
   - 轻微几何畸变（±2% 缩放/旋转）→ 模拟非原模压制
3. 标注：真品=0，退化图=1
4. 注意：这类模型学到的是"工艺异常"，**不是真伪判决**，对外表述必须是"存疑"

**路径 B：采购/借展已知仿品（最有效，要钱）**

- 文玩市场、电商平台的"高仿/工艺币"，20~50 枚即可起步
- 每枚拍正反面，按真品同样标准处理
- 成本：约 50~200 元/枚，预算 2,000 元可拿 15~30 枚
- 优点：真实仿品分布，模型有实际意义

**路径 C：收集公开的赝品对比图（有版权风险）**

论坛、公众号的"真假对比"图。**只能参考，不能直接入训练集**，版权与授权都成问题。

> **建议**：先用路径 A 跑通全流程（一周内可完成），同时用预算走路径 B。
> A 的模型上线后标为"工艺异常初筛"，B 的数据到了再升级。

### 3.3 数据划分（务必遵守）

**按钱币为单位划分**，不能按图随机切。理由：同一枚币的正反面与增强副本必须落在同一集合，
否则验证集包含训练见过的图，指标虚高——项目里已经踩过这个坑
（见 `docs/数据与工程质量修复.md` 第二节）。

可直接复用 `scripts/split_dataset.py` 的并查集分组逻辑。

建议比例：训练 70% / 验证 10% / 测试 20%，且**真假两类在三个集合中的比例一致**。

### 3.4 训练建议

| 项目 | 建议 |
|---|---|
| 骨干 | 与版式模型一致（VGG19 双路）或 ResNet50 双路 |
| 输入 | 正反面各一张，通道维拼接（与现有模型保持一致） |
| 损失 | 交叉熵；类别不均衡时用加权交叉熵（真:假 = 1:2 左右） |
| 增强 | 只做几何与光照（旋转、翻转、亮度、对比度），**不要用模糊类增强**——那会抵消"模糊"这一负样本特征 |
| 训练轮数 | 以验证集早停为准 |
| 导出 | `torch.onnx.export`，`opset=13`，dynamic_axes 允许 batch 可变 |

### 3.5 必报的指标（写进材料的数）

| 指标 | 说明 |
|---|---|
| 准确率 / 精确率 / 召回率 | 分真假两类分别给 |
| **假币召回率** | 最重要。漏判假币的代价远大于误判真品 |
| 混淆矩阵 | 必给 |
| 测试集规模与构成 | 必须写明真假各多少、来源 |

**不要只报准确率。** 真假样本不均衡时，准确率会骗人。

### 3.6 怎么验证接入成功

```bash
# 1. 把导出的模型放到指定位置
cp your_model.onnx backend/authenticity.onnx

# 2. 查接入状态
curl http://127.0.0.1:5001/api/authenticity/capabilities
# 期望：model.ready = true, model.output_dim = 2

# 3. 传图测试
curl -X POST http://127.0.0.1:5001/api/authenticity/check \
     -F "image1=@front.jpg" -F "image2=@back.jpg"
# 期望：status = "ok"，risk_level 有值，score 在 0~1

# 4. 打开页面
# http://127.0.0.1:5001/authenticity
```

**如果 `model.ready` 为 false**，按这个顺序查：
1. 文件是否在 `backend/authenticity.onnx`
2. 输出维度是否为 2（`capabilities.model.output_dim`）
3. 输入名是否为 `input1` / `input2`（系统按输出顺序取前两个输入，一般无需改名）

## 四、多模态问答：已通了什么

### 4.1 接口

`POST /api/ask`（multipart 或 JSON 均可）

```
question  问题（必填）
images    1~2 张图片（可选）
stream    true 时返回 SSE 流
history   多轮历史
```

### 4.2 数据流

```
用户提问（可带图）
   ↓
若有图：版式识别 → 得到「疑似 XXX」
   ↓
知识检索（图谱 local / 全局 global / 联网 web）
   ↓
并入「部位级鉴别要点」（本轮新增）
   ↓
大模型生成 → 回答 + 出处 + 模态标记
```

### 4.3 本轮改动

- 图片问答的上下文里**自动并入该币种的部位提示**，使回答能落到"看哪里"
- 响应新增 `modalities` 字段：`["text"]` 或 `["text","image"]`，便于前端区分
- 前端问答组件支持图片上传（原有）

### 4.4 回答必须满足的三条

1. **有出处**：来源列表非空，或明确说明"资料库无相关记录"
2. **不编造**：检索不到就说检索不到
3. **图片结论降级表述**：图为"疑似 XXX"，不给确定判断

## 五、当前能力边界（如实告知用户）

| 能做 | 不能做 |
|---|---|
| 提示该看哪些部位、正品什么样 | 判定真伪 |
| 给出风险等级（模型接入后） | 替代专业评级 |
| 回答历史、版别、形制、价格常识 | 回答资料库未覆盖的币种 |
| 识别已覆盖类目的版式 | 识别未覆盖类目 |

界面上必须体现这些边界，不能默认用户知道。

## 六、提示库怎么扩量（真伪功能的真正瓶颈）

当前只有 13 条。扩量有三个来源：

| 来源 | 预期产出 | 成本 |
|---|---|---|
| 纸质图录（《中国机制银圆目录》等） | 每个币种 3~5 条部位要点 | 书费约 1,200 元 |
| 拍卖行图录的拍品描述 | 大量品相与形制描述 | 免费（注意版权，需改写） |
| 藏家访谈 | 最贴近实战的鉴别经验 | 访谈 2~3 位 |

格式要求（写入 `part_hints.json` 前必须满足）：

```json
{
  "part": "边齿",
  "text": "边齿为等距直齿，齿槽深峻且平行，仿品常见激光切割齿纹",
  "judged": true,
  "source": "藏家访谈/2026-11-05"
}
```

- `part` 只能取：边齿 / 珠圈 / 字口 / 包浆 / 重量 / 声音
- 一条只讲一个部位
- 必须能指出正品特征或仿品特征（`judged=true` 优先展示）
- **必须带来源**
